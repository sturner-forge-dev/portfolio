# Repository Instructions

## Project Shape

- This is a small Astro 6 portfolio site using npm; `package-lock.json` is the lockfile, so use npm commands.
- Pages live in `src/pages/`; shared shell is `src/layouts/BaseLayout.astro`; reusable UI is in `src/components/`.
- Work/project case studies are Astro content collection entries in `src/content/work/*.md`; their schema is enforced in `src/content.config.ts`.
- Global design tokens, theme colors, utility classes, and font imports are centralized in `src/styles/global.css`.

## Commands

- Install: `npm install`.
- Dev server: `npm run dev` (Astro default `localhost:4321`).
- Production build and Astro validation: `npm run build`.
- Preview built output: `npm run preview`.
- Lint: `npm run lint`.
- Format all files: `npm run format`; check formatting without writes: `npm run format:check`.
- There is no test script or CI workflow in this repo; use `npm run lint`, `npm run format:check`, and `npm run build` as the normal verification set.

## Tooling Notes

- ESLint uses flat config in `eslint.config.js`; it ignores `.astro/` and `dist/`, and intentionally disables `@typescript-eslint/no-unused-vars`.
- Prettier uses tabs, single quotes, `printWidth: 120`, and `prettier-plugin-astro`; do not hand-convert indentation to spaces in formatted files.
- TypeScript extends `astro/tsconfigs/strict`; there is no separate `typecheck` script, but `astro build` checks Astro/TS issues during build.
- `astro.config.mjs` sets `site: 'https://steventurner.dev'`, sitemap integration, `base: '/'`, and output to `./dist`.

## Content And Routing Gotchas

- Dynamic work pages are generated by `src/pages/work/[...slug].astro` from `getCollection('work')`; Markdown filenames become slugs via `entry.id`.
- New work Markdown must include `title`, `description`, `publishDate`, `tags`, `img`, and optional `img_alt` to satisfy the content schema.
- Several links/assets derive `BASE_PATH` from `import.meta.env.BASE_URL.replace(/\/$/, '')`; preserve this pattern if adding root-relative links in pages/components.
- Images rendered through `astro:assets` should use paths compatible with Astro image handling; existing work entries store image paths in frontmatter.
